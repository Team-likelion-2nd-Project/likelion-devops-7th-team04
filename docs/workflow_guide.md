## 2. 📋 단계별 자동화 처리 상세

| 단계 | 발생 작업 (Trigger) | GitHub Actions 자동 연동 동작 | Jira 보드 상태 | Slack 알림 |
| :---: | :--- | :--- | :---: | :---: |
| **1** | GitHub 이슈 생성 (마일스톤 지정) | 마일스톤 연동 Jira 에픽 탐색 후 **하위 Task 자동 생성** | **`해야 할 일`** | 🔔 Task 생성 |
| **2** | `feature/DEV-16` 브랜치 생성 | 브랜치명의 Jira 키(`DEV-16`)를 감지하여 상태 이관 | **`진행 중`** | 🔔 진행 중 |
| **3** | PR 생성 (설명에 `Closes #이슈번호`) | PR 감지 및 연결된 Jira Task 상태 이관 | **`검토 중`** | 🔔 PR 검토 요청 |
| **4-1** | 리뷰어 반려 (`Request Changes`) | 반려 감지 후 수정 작업 상태로 이관 | **`진행 중`** | - |
| **4-2** | 코드 수정 후 Push / 🔄 재요청 | 수정한 코드 Sync 또는 재요청 감지 후 상태 재이관 | **`검토 중`** | 🔔 재검토 요청 |
| **6** | 리뷰어 승인 (`Approve`) 후 PR Merge ➔ GitHub 이슈 닫힘 | GitHub 이슈 `Closed` 감지 후 최종 완료 처리 | **`완  료`** | 🔔 개발 완료 |

## 💻 3. 개발자 작업 가이드 (Step-by-Step)

### Step 1. 작업 할당 및 브랜치 생성
1. **담당자 지정:** Jira 보드의 **`해야 할 일`** 컬럼에서 본인이 작업할 Task를 선택하고 담당자(Assignee)를 자신으로 지정합니다.
2. **브랜치 생성:** Jira 이슈 우측 **[개발(Development)] ➔ [브랜치 만들기(Create Branch)]**를 클릭하여 브랜치를 생성합니다.
   * **브랜치명 규칙:** 브랜치 정책 문서 참조
   * 💡 **자동화 포인트:** 브랜치가 생성되면 Jira 상태가 **`진행 중`**으로 자동 이동하며 Slack 알림이 전송됩니다.

---

### Step 2. 개발 및 푸시 (Push)
1. 생성된 브랜치로 스위칭한 후 로컬 환경에서 개발을 진행합니다.
2. 개발 완료 후 작업 내용을 Remote 저장소로 `push`합니다.
   ```bash
   git add .
   git commit -m "feat: 로그인 API 구현 (#DEV-16)"
   git push origin DEV-16-로그인-API-구현
---

### Step 3. Pull Request (PR) 작성
1. GitHub에서 PR을 생성합니다.
2. PR 본문에 연결된 **GitHub 이슈 번호**를 반드시 기재합니다. (예: `Closes #10` 또는 `Fixes #10`)
   * 💡 **자동화 포인트:** PR이 생성되면 Jira 상태가 `검토 중`으로 자동 이동하고 Slack에 리뷰 요청이 전송됩니다.
   * 💡 **자동화 포인트:** PR이 생성되면 자동으로 PR 제목 앞에 지라키를 추가합니다. `[DEV-16] 로그인 API 기능 구현`

---

### Step 4. 코드 리뷰 및 피드백 반영

* **case A. 승인 (Approve) & Merge:**
  1. 관리자/리뷰어가 PR을 승인하고 **Merge**를 진행합니다.
  2. 연결된 GitHub 이슈가 자동으로 닫히며(Closed), Jira Task도 **`완료`** 상태로 자동 이동합니다.

* **case B. 반려 (Request Changes):**
  1. 리뷰어가 수정 요청을 남기면 Jira Task가 다시 **`진행 중`** 상태로 자동 전환됩니다.
  2. 로컬에서 코드를 수정한 뒤 다시 `push` 하거나, PR 화면 우측 Reviewers 항목에서 **🔄 (Re-request review)** 버튼을 누릅니다.
  3. Jira Task가 다시 **`검토 중`** 상태로 자동 전환됩니다.

---

## ⚠️ 워크플로우 진행시 주의사항

1. **브랜치명 규칙:** 브랜치명에는 반드시 Jira 이슈 키(예: `DEV-123`)가 포함되어야 자동화 액션이 동작합니다.
2. **이슈 자동 닫기 연동:** PR 본문에 `Closes #이슈번호` (예: `Closes #10`)를 적어주셔야 PR Merge 시 GitHub 이슈가 자동으로 Closed 처리됩니다.
3. **수동 변경 지양:** Jira 보드 상에서 카드를 수동으로 드래그하여 옮기지 않아도 GitHub 액션에 의해 100% 자동 관리됩니다.
4. **브랜치 복귀:** 작업 완료 후, 현재 브랜치에서 develop 브랜치로 이동하여 `git pull` 명령어를 실행하여 로컬 레파지토리를 동기화 시킵니다.
